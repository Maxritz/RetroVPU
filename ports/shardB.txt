### Debug-hypothesis blocks to implement (R1 compliance):

1. **H-GEMV-TILE-1:** For sgemv no-transpose, SLM tile of 256×64 (rows×K-chunk)
   saturates L2 bandwidth on Xe-LPG. Below 256 outputs, dispatch overhead
   dominates. Decision rule: if M < 512 → CPU; if M ≥ 512 → GPU with tile.
   *Test:* sweep M from 64 to 8192, compare GPU-tiled vs CPU-OpenBLAS at
   equal thread count. Kill if GPU <5% faster at M ≥ 512.

2. **H-GEMV-TRANS-1:** Transpose GEMV (y = A^T x) has no data sharing between
   output elements. Hypothesis: SLM tile does not help; GPU only wins when
   M × K > L2 size. Decision: if M×K > 16M elements → GPU SLM tile;
   else CPU. *Test:* vary M=1..8192, K=1..8192; measure bandwidth
   (GB/s) for both paths.

3. **H-SYMM-ELIDE-1:** ssymv with V12.ELIDE (skip upper triangle) computes
   N(N+1)/2 vs N² elements. Hypothesis: GPU wins only when the 2x work reduction
   + SLM tile overcomes dispatch overhead. Decision: triangle size > 4096²
   → GPU; else CPU. *Kill:* if elision saves < 10% at 4096².

4. **H-TRSV-SEQUENTIAL-1:** Forward substitution is inherently sequential
   along the diagonal. Hypothesis: GPU panel-solve with V12.REDUCE for
   panel-level parallelism only beats CPU when panel count > EU count (128).
   *Kill:* if M < 128×128 → force CPU.
